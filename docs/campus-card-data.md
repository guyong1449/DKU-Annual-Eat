# 校园卡数据口径

2026-11-16 核查已登录的校园卡页面及其表单、行结构和内嵌调用代码。

| 入口 | 当前可核实的用途 | 信息边界 |
| --- | --- | --- |
| `GET /dku/index` | 账户页面、交易查询表单、近半年消费走势图 | 走势图由页面内嵌数据调用 `cntstat` 绘制，未发现独立的菜品统计调用 |
| `POST /dku/searchmydtl` | `dtlsearch` 和 `pageSubmit` 均调用它，返回分页交易 HTML | 5 列：创建时间、类型/交易号、对方名称、金额、状态；每页 6 条 |
| `GET /dku/deposit` | 页面 `showDepositBill` 中的账单跳转入口 | 仅核实入口，未核实返回内容；不能据此声称能追溯菜品 |
| `GET /dku/feebill` | 页面 `showFeeItemBill` 中的费用账单跳转入口 | 仅核实入口，未核实返回内容 |

流水查询字段为 `pageNo`、`pager.offset`、`_csrf`、`accid`、`startdate`、`enddate`。交易行没有可展开的明细链接，也没有独立的菜品、历史经营名称、收款终端编号等字段。页面上还有充值、挂失等操作入口，与本次只读交易核查无关，未调用。

以上是本次已登录页面的证据范围，不代表枚举了学校所有后端接口。浏览器控制连接多次超时，账单页面及外链脚本未完成返回内容核验。

## 消费报告

- 只从校园卡返回名称中提取明确的窗口编号，如 `1F-2`。同一名称反复出现同一编号不影响识别；包含多个不同编号时保留原名，不猜测归属。
- 金额排行、占比和窗口月度曲线按这个编号归集。同楼层、相邻位置或“西侧”不作为合并依据；没有编号的商户保留原名。
- 校园卡可能把同一收款窗口不同经营时期的交易显示为同一个名称。`1F-2` 的消费金额不能解释成“吃面的金额”，也不能从时间或价格反推出蛋包饭等具体菜品。
- 窗口详情列出校园卡返回名称，逐笔记录保留原样。原始 JSON 不重写；退款配对和消费金额计算保持原口径。

## Eat TI

Eat TI 继续读取原始 `merchant`、时间、金额及原有清洗结果。角色匹配、餐饮识别、门槛、排序和趣味分布均不改变。财务窗口名称归集不会把新标签写回这些输入，因此不会静默改变已有 Eat TI 结果。
